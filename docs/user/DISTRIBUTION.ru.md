# Установка, миграция и выпуск Чифа

## Установка в проект

В распакованном комплекте откройте `install.cmd` (Windows) или выполните
`sh install.sh` (Linux). Выбор в первой строке определяет, что проверит мастер.

| Среда | Что понадобится | Что открывать после установки |
| --- | --- | --- |
| OpenCode | OpenCode Desktop и его CLI. В Linux при отсутствии комплектного CLI установите команду `opencode` в PATH | Мастер настройки моделей и затем Desktop |
| Pi | Совместимый пакет Pi 1.3.0 и Node.js или Node.js 22.19+ с npm для его установки в проект | Pi в папке проекта |
| Codex | Codex CLI с доступом пользователя к своей модели | Codex в папке проекта |
| Claude Code | Claude Code CLI с доступом пользователя к своей модели | Claude Code в папке проекта |

Если нужный CLI появился после открытия окна, нажмите кнопку повторной проверки.
Для повторного запуска используйте `start.cmd` или `sh start.sh` из проекта.
Новая установка начинается в режиме обычного агента. Дашборд включает Чифа.
Модели, права и условия доступа задаёт соответствующий провайдер. Для настройки
рабочих процессов см. [руководство по проекту](PROJECT_DOCUMENTATION.ru.md).

У обычного профиля Pi и управляемой команды могут быть разные версии. В новой
установке обычный запуск берёт Pi из PATH, а команда Чифа использует закреплённый SDK.
Мастер загружает его в `.tools/pi`, если подходящего пакета ещё нет. Для первой
загрузки нужен доступ к npm. Старая установка Pi сохраняет ссылку на свою среду.

## Обновление установки OpenCode или Pi

Распакуйте новую поставку отдельно от приложения и укажите мастеру прежнюю
папку проекта. Для старой установки Pi предварительно завершите активный терминал
Pi и остановите службу проекта. Первичный манифест Pi хранится в
`.metrics/.pi-kit-installation.json`. Общий манифест — `.metrics/.kit-installation.json`.
При миграции сохраняются прежний манифест, `pi-kit.json`, локальные настройки,
код приложения, история задач и привязка базы Obsidian. Зарегистрированная ранее
папка среды Pi (`.pi/installation.json`) по-прежнему должна быть доступна.

Для автоматизации выполните из каталога **новой поставки**:

```powershell
.\install.cmd --update "D:\Projects\Мой проект" --preview
.\install.cmd --update "D:\Projects\Мой проект"
```

В Linux используйте `sh install.sh --update "/путь/к/проекту" --preview`, затем
повторите команду без `--preview`. Просмотр показывает добавления, замены,
конфликты и снятые с поставки пути. При первой миграции Pi конфликт останавливает
принятие старого манифеста до записи нового. Для уже общей установки команда
обновления может применить независимые файлы и оставить изменённые владельцем
пути в списке конфликтов. После прерывания повторите команду из той же поставки.

## Как устроен выпуск в Git и GitHub

1. **Коммит** фиксирует дерево проверенных исходников. Локальные незакоммиченные
   изменения в этот снимок не входят. Для выпуска выберите точный SHA.
2. **Тег** даёт этому коммиту постоянное имя версии. Пример локальной команды
   для уже выбранного SHA — `git tag -a v1.2.0 COMMIT_SHA -m "Чиф 1.2.0"`.
   Команда `git show v1.2.0` показывает, какой коммит отмечен. Отправка тега в
   удалённый репозиторий — отдельное действие. [Руководство Git по тегам](https://git-scm.com/book/en/v2/Git-Basics-Tagging).
3. **Сборка** создаёт пользовательский архив из проверенного дерева. В чистой
   копии выбранного коммита выполните
   `python -m kit.release_archive --version 1.2.0 --output dist` через Python
   комплекта. Сборщик сверяет состав и байты файлов и выводит SHA-256 ZIP.
   Проверьте распаковку, установку и обновление обеих старых версий.
4. **GitHub Release** связывает тег, заметки об изменениях и прикреплённые
   файлы. Для управления выпуском нужны права записи в целевой репозиторий.
   GitHub также предлагает ZIP и tar.gz исходников из тега. В публичном
   репозитории они доступны всем. [Документация GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

Поставку Чифа собирают в основном репозитории `polar-byter/opencode-environmental-tune`.
Прежний отдельный репозиторий `polar-byter/pi-agent-kit` удалён 15 ноября 2026 года.
Для обновления старого проекта Pi используйте общий комплект и порядок обновления выше.
Для конкретной публикации владелец задаёт версию, целевое
место, видимость и состав файлов. Локальная сборка пригодна для проверки до публикации.

### Действия в интерфейсе GitHub

1. После проверки сборки убедитесь, что в целевом репозитории доступен тег выбранного коммита.
2. Откройте **Releases → Draft a new release**. В списке тегов выберите версию выпуска.
3. Введите название и кратко опишите изменения и порядок обновления. Прикрепите проверенный
   установочный ZIP и файл с его SHA-256. GitHub отдельно добавит архивы исходников.
4. Кнопка **Save draft** сохранит черновик. Когда тег, файлы и описание сверены,
   нажмите **Publish release**. После публикации откройте страницу версии и проверьте,
   что установочный ZIP скачивается и его SHA-256 совпадает с проверенным.
   [Создание выпусков в GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).
