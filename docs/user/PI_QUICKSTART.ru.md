# Как запустить Чифа в Pi

Эти шаги относятся к проекту с комплектом `kit/` этой ветки. По умолчанию
используется OpenCode. Сначала завершите активные задачи, если переводите
существующий проект на Pi. Журнал хранит принадлежность задачи к среде.
Для независимой пробы удобно использовать отдельную рабочую копию.

В свежей установке сначала включите режим командой
`.\kit\python.cmd -m kit.chief_mode on` или переключателем под выбором задачи
в дашборде. В режиме `off` можно сразу запускать установленный у вас Pi с обычным профилем.

1. Установите в корне проекта версию Pi, с которой проверялись RPC и права
   исполнителя. Нужны Node.js и npm. Локальная установка не меняет глобальный Pi.

   ```powershell
   npm install --prefix .tools/pi --no-package-lock --no-audit --no-fund @earendil-works/pi-coding-agent@1.3.0
   ```

2. Создайте в корне `pi-kit.json` с содержимым `{"runtime":"pi"}`.
   Создайте или найдите файл локальных настроек командой
   `.\kit\python.cmd -m kit.run_pi --configure`. В `.pi/kit-models.json`
   укажите выбранные вами роли. Вместо значений в угловых скобках нужны
   настоящие идентификаторы доступных моделей Pi.

   ```json
   {
     "masterChief": {"source": "pi", "model": "<provider>/<chief-model>"},
     "executors": {"source": "pi", "model": "<provider>/<worker-model>"},
     "bugFixer": {"source": "pi", "model": "<provider>/<fixer-model>"}
   }
   ```

3. Если провайдер требует входа, запустите
   `.\kit\python.cmd -m kit.run_pi --authenticate`, используйте `/login` и
   закройте сеанс командой `/quit`. Подготовьте настройки командой
   `.\kit\python.cmd -m kit.run_pi --prepare-only`. Подготовка проверяет
   конфигурацию, собирает промпты ролей и записывает `.pi/kit-runtime.json`.
   Модельный запрос на этом шаге не нужен.
4. Для работы в терминале выполните `.\kit\python.cmd -m kit.run_pi`.
   Для управляемой RPC-сессии используйте `--headless`. Уточнить параметры
   можно через `--help`. На Linux вместо Windows-обёртки используйте
   `sh kit/python.sh`. Брокер проекта хранит привязки сессий в `.pi/kit-service/`.

В Git хранятся исходники и выбор среды. Локальные настройки Pi и сторонние
пакеты лежат в каталогах `.pi/` и `.tools/`, исключённых из снимка исполнителя.
В терминальном и RPC-режимах Чиф получает общий скилл комплекта. Исполнители
получают поручения своей роли. Состояние проверок и оставшиеся этапы — в
[спецификации](../kit/UNIVERSAL_KIT_SPEC.ru.md).
